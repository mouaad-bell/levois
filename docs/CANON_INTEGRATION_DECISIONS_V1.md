# LEVOIS — Canon Integration Decisions V1

Date : 19 septembre 2026.

Source prioritaire : **LEVOIS — Contenu et expérience — Document canonique V1**.

Ce fichier enregistre les arbitrages nécessaires entre le moteur éditorial construit avant le canon et les règles désormais canoniques.

## 1. Le hook n’est plus le point de départ

Avant : le Studio pouvait chercher un hook très tôt puis organiser le dossier autour de lui.

Maintenant :

1. décision ;
2. lecture spontanée ;
3. élément qui la met à l’épreuve ;
4. conclusion autorisée ;
5. opération autonome ;
6. démonstration ;
7. trois ouvertures ;
8. sélection du hook.

Conséquence : une intuition de hook peut lancer une recherche, mais ne devient jamais automatiquement un titre publiable.

## 2. Les trois ouvertures sont obligatoires avant sélection

Le moteur produit :

- une ouverture directe ;
- une ouverture-scène ;
- une ouverture-comparaison.

Elles promettent la même démonstration. Elles peuvent utiliser des familles différentes du canon.

## 3. Les quatre contrôles remplacent les heuristiques génériques

Le hook est relu selon :

- Temps ;
- Sens ;
- Miroir ;
- Écart.

Les critères génériques de type « clickbait », « curiosité maximale » ou « taux de rétention » ne peuvent jamais supplanter ces contrôles.

## 4. Le nombre de slides n’est plus canonique

Ancienne préférence : 7 à 10 slides.

Nouvelle règle : le nombre dépend du raisonnement. La limite technique du renderer peut rester, mais elle n’est pas présentée comme une loi éditoriale.

Le moteur ne peut pas ajouter des slides pour retarder une réponse.

## 5. Le plafond de mots n’est plus une loi

Les seuils de densité restent des garde-fous de rendu mobile.

Ils peuvent déclencher une alerte ou une recomposition, pas transformer automatiquement un contenu exact en contenu invalide.

## 6. La méthode n’est pas obligatoirement en trois étapes

Trois opérations restent une excellente forme lorsqu’elles couvrent le raisonnement.

Mais le canon n’impose aucun nombre universel. La méthode doit surtout être interprétable et réutilisable.

## 7. Le CTA n’est plus une condition de fin

La résolution principale et l’action autonome viennent avant tout CTA.

Une dernière slide peut simplement transmettre la méthode.

Un bridge LEVOIS existe seulement s’il ajoute une suite réelle et cohérente.

## 8. Save Value et Share Value changent de statut

Ils restent utiles à la conception et à l’apprentissage de performance.

Ils ne sont plus des conditions de vérité ou de publication.

Une personne peut obtenir une réponse utile et repartir sans sauvegarder, partager ou contacter.

## 9. La progression devient explicite

Le moteur doit couvrir six fonctions :

1. situation ;
2. lecture initiale ;
3. friction ;
4. démonstration ;
5. relecture ;
6. prise pratique.

Chaque beat conserve un état `before` et `after`. Si la compréhension ne change pas, le beat est à supprimer ou fusionner.

## 10. Le site et le contenu utilisent la même affirmation qualifiée

Chaque claim issu de la bibliothèque conserve :

- evidence_id ;
- source ;
- statut ;
- périmètre ;
- date ;
- allowed_uses ;
- forbidden_inferences.

Le wording public peut varier par format, mais pas le degré de certitude.

## 11. Les trois vetos absolus entrent dans le moteur

1. fait fabriqué présenté comme réel ;
2. peur non justifiée par le dossier ;
3. résolution remplacée par une obligation commerciale.

Une performance observée ne peut jamais lever ces vetos.

## 12. Les fixtures précédentes sont requalifiées

`80 m². Où passe la place ?`, `Plus loin. De quoi ?` et `25 000 € d’écart. Trop chère ?` restent des pistes de création.

Elles doivent être réévaluées selon le canon avant toute production finale.
